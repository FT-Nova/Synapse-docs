# Monitoring & Observability

SYNAPSE exposes Prometheus metrics at `/actuator/prometheus`. Integrate with your existing monitoring stack or use the bundled Prometheus + Grafana setup.

## Metrics Endpoint

The metrics endpoint is available after starting SYNAPSE:

```
GET http://localhost:8080/actuator/prometheus
```

All metrics are tagged with:

```
application=synapse-core
version=<synapse-version>
service=synapse-core
```

---

## Option 1: Use Existing Prometheus

If you already have Prometheus running, add SYNAPSE as a scrape target:

```yaml
# Add to your existing prometheus.yml
scrape_configs:
  - job_name: 'synapse-backend'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['<synapse-host>:8080']
        labels:
          application: 'synapse-core'
          environment: 'production'
```

Reload Prometheus:

```bash
curl -X POST http://localhost:9090/-/reload
```

---

## Option 2: Bundled Prometheus + Grafana

For standalone deployments, use the included monitoring compose profile:

```bash
cd installer/compose
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml --profile monitoring up -d
```

This starts:

| Service | URL | Credentials |
|---------|-----|-------------|
| Prometheus | `http://localhost:9090` | — |
| Grafana | `http://localhost:3001` | `admin` / `admin` |

The Prometheus datasource and SYNAPSE dashboards are pre-configured in Grafana.

Import dashboards from `installer/compose/grafana/dashboards/` if not auto-loaded.

## Available Metrics

### System Metrics

| Metric prefix | What it measures |
|---------------|-----------------|
| `jvm_*` | JVM memory, GC, threads |
| `http_server_requests_*` | HTTP request counts, latency |
| `hikaricp_*` | Database connection pool |
| `lettuce_*` | Redis connections |

### Application Metrics

| Metric | Description |
|--------|-------------|
| `synapse_agent_invocations_total` | Agent invocation count |
| `synapse_agent_active_sessions` | Currently active agent sessions |
| `synapse_messages_total` | Conversation messages processed |
| `synapse_provider_requests_total` | Model provider API calls |
| `synapse_plugin_*` | Plugin operation metrics |

## Example Queries

### Request Rate by Endpoint
```promql
rate(http_server_requests_seconds_count{uri!="/actuator/prometheus"}[5m])
```

### 95th Percentile Response Time
```promql
histogram_quantile(0.95, rate(http_server_requests_seconds_bucket[5m]))
```

### Active Agent Sessions
```promql
synapse_agent_active_sessions
```

### Error Rate
```promql
rate(http_server_requests_seconds_count{status=~"5.."}[5m])
```

### JVM Memory Usage
```promql
jvm_memory_used_bytes{application="synapse-core"}
```

## Production Considerations

### Metrics Retention

Default bundled Prometheus retention: **15 days**

To extend:

```yaml
# docker-compose.monitoring.yml
prometheus:
  command:
    - '--storage.tsdb.retention.time=30d'
```

### Service Discovery

For dynamic environments (Kubernetes, Consul), use service discovery instead of static targets:

```yaml
# kubernetes_sd_configs example
scrape_configs:
  - job_name: 'synapse'
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_label_app]
        action: keep
        regex: synapse-backend
```

### Remote Storage

For long-term retention, configure remote write to Thanos, Mimir, or VictoriaMetrics:

```yaml
remote_write:
  - url: 'http://thanos-receive:19291/api/v1/receive'
```

### Performance Impact

Metrics scraping is lightweight:
- Endpoint response: `<10ms`
- Memory footprint: `~5MB`
- CPU impact: `<1%` per scrape

## Alerting

### Critical Alerts (Prometheus AlertManager)

```yaml
groups:
  - name: synapse
    rules:
      - alert: SynapseDown
        expr: up{job="synapse-backend"} == 0
        for: 1m
        labels:
          severity: critical

      - alert: HighErrorRate
        expr: rate(http_server_requests_seconds_count{status=~"5.."}[5m]) > 0.1
        for: 5m
        labels:
          severity: warning

      - alert: HighMemoryUsage
        expr: jvm_memory_used_bytes / jvm_memory_max_bytes > 0.85
        for: 10m
        labels:
          severity: warning
```

## Troubleshooting

### Metrics endpoint returns 404

Ensure `spring-boot-starter-actuator` and `micrometer-registry-prometheus` are in the backend dependencies. Check `application.yml`:

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus
```

### No metrics scraped by Prometheus

1. Check targets: `http://localhost:9090/targets`
2. Verify backend is reachable from the Prometheus container
3. Check Prometheus logs: `docker compose logs prometheus`

### Grafana shows "No data"

1. Verify Prometheus datasource: **Configuration → Data Sources → Prometheus → Test**
2. Adjust time range (dashboards default to last 6 hours)
3. Confirm metrics are flowing: check Prometheus UI `http://localhost:9090`
