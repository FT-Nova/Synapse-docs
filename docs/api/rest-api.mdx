# REST API Reference

This page documents core operational endpoints, including observability, memory-tier APIs, and agent collaboration APIs.

## Health Endpoints

### `GET /api/health`

High-level platform health response.

Example response:

```json
{
  "systemName": "SYNAPSE",
  "version": "v2.1.4-dev",
  "status": "UP",
  "echoEnabled": true,
  "echoDebugOnly": true,
  "echoActivation": "manual",
  "timestamp": "2026-05-10T20:00:00Z"
}
```

### `GET /api/health/liveness`

Liveness probe endpoint for platform/container health checks.

Example response:

```json
{
  "status": "UP",
  "checks": {
    "application": "UP"
  },
  "timestamp": "2026-05-10T20:00:00Z"
}
```

### `GET /api/health/readiness`

Readiness probe endpoint for dependency validation.

Checks include:

- database connectivity
- redis connectivity
- qdrant availability (optional via env toggle)
- configured provider health

Example response:

```json
{
  "status": "UP",
  "checks": {
    "database": "UP",
    "redis": "UP",
    "qdrant": "UP",
    "providers": "UP"
  },
  "timestamp": "2026-05-10T20:00:00Z"
}
```

## Actuator Endpoints

### `GET /actuator/health`

Spring Boot actuator health endpoint with probe groups enabled.

### `GET /actuator/prometheus`

Prometheus metrics scrape endpoint.

Use this with:

- existing Prometheus in homelab/enterprise
- bundled Prometheus in `docker-compose.monitoring.yml`

## Trace Context

SYNAPSE logging and events propagate the following context fields:

- `traceId`
- `spanId`
- `correlationId`

This allows request tracing across API logs and Redis event stream entries.

## Agent Memory Endpoints

### `GET /api/agents/{agentId}/memory`

List memory entries for an agent.

Optional query params:
- `namespace`
- `tier` (`SHORT_TERM`, `KNOWLEDGE`, `ARCHIVE`)

### `GET /api/agents/{agentId}/memory/{key}`

Get one memory entry by key.

### `PUT /api/agents/{agentId}/memory/{key}`

Upsert a memory entry (defaults to `SHORT_TERM` on first write).

Body:

```json
{
  "key": "project.summary",
  "value": "Current sprint focus is memory tiering",
  "namespace": "project"
}
```

### `POST /api/agents/{agentId}/memory/{key}/promote`

Promote an entry to another tier with explicit reason.

Body:

```json
{
  "targetTier": "KNOWLEDGE",
  "reason": "MANUAL"
}
```

Allowed transitions:
- `SHORT_TERM -> KNOWLEDGE`
- `SHORT_TERM -> ARCHIVE`
- `KNOWLEDGE -> ARCHIVE`

### `DELETE /api/agents/{agentId}/memory/{key}`

Delete a memory entry by key.

## Agent Collaboration Endpoints

Base path: `/api/teams/{teamId}/collaboration`

### `GET /sessions`

List collaboration sessions for a team.

### `POST /sessions`

Create a new active collaboration session.

Body:

```json
{
  "initiatedByAgentId": "main-agent",
  "conversationId": "b4de5a2f-8cc9-4acd-9be8-3efa6bcddaca"
}
```

### `GET /sessions/{sessionId}`

Get one session by ID (team-scoped).

### `GET /sessions/{sessionId}/messages`

List inter-agent messages in chronological order.

### `POST /sessions/{sessionId}/messages`

Send a typed inter-agent collaboration message.

Body:

```json
{
  "fromAgentId": "main-agent",
  "toAgentId": "worker-agent",
  "messageType": "DIRECTIVE",
  "content": "Handle task decomposition for milestone v2.4.0",
  "metadata": {
    "priority": "high"
  }
}
```

Message types:
- `DIRECTIVE`
- `CONTEXT`
- `STATUS`
- `RESULT`

### `GET /sessions/{sessionId}/delegations`

List task delegation records for a session.

### `POST /sessions/{sessionId}/delegations`

Create a delegation from one team member to another.

Body:

```json
{
  "taskId": "ec4d1d99-156f-4678-8078-710cb2f28361",
  "fromAgentId": "main-agent",
  "toAgentId": "worker-agent",
  "delegationNote": "Implement collaboration routing"
}
```

### `GET /sessions/{sessionId}/context`

List shared context entries for a collaboration session.

### `PUT /sessions/{sessionId}/context/{contextKey}`

Create/update a shared context key (version increments on update).

Body:

```json
{
  "value": "routing implemented, tests pending",
  "updatedByAgentId": "worker-agent"
}
```

## Agent Planning Endpoints

Base path: `/api/teams/{teamId}/planning`

### `GET /goals`

List planning goals for a team.

### `POST /goals`

Create a planning goal.

Body:

```json
{
  "collaborationSessionId": "7ad8c0bd-7166-418e-bf4b-8fb4f37f5fef",
  "title": "v2.4.0 delivery",
  "goalStatement": "Deliver roadmap milestones with minimal token cost",
  "createdByAgentId": "main-agent"
}
```

### `GET /goals/{goalId}`

Get one planning goal.

### `GET /goals/{goalId}/plans`

List plan versions for a goal (newest first).

### `POST /goals/{goalId}/plans`

Create the initial plan artifact.

Body:

```json
{
  "compactSummary": "Three-step plan focused on collaboration, validation, and release",
  "steps": [
    { "id": "s1", "title": "Implement feature", "status": "PENDING" },
    { "id": "s2", "title": "Validate behavior", "status": "PENDING" },
    { "id": "s3", "title": "Ship release", "status": "PENDING" }
  ],
  "reasoningChain": [
    { "summary": "Prioritize implementation first to unblock test and release phases" }
  ],
  "createdByAgentId": "main-agent"
}
```

### `POST /goals/{goalId}/plans/refine`

Refine/adapt an existing plan and create a new version.

Body:

```json
{
  "basePlanId": "0e08f368-b73e-4f73-8826-8f1ed0cd39f5",
  "compactSummary": "Updated plan after risk review",
  "steps": [
    { "id": "s1", "title": "Implement feature", "status": "DONE" },
    { "id": "s2", "title": "Validate behavior", "status": "IN_PROGRESS" },
    { "id": "s3", "title": "Ship release", "status": "PENDING" }
  ],
  "reasoningChain": [
    { "summary": "Adapted order to close discovered regression before release" }
  ],
  "createdByAgentId": "main-agent"
}
```

### `GET /goals/{goalId}/next-step`

Return the next non-`DONE` step from the active plan version.

## Native Tool Endpoints

Base path: `/api/tools`

### `GET /`

List registered native Java tools.

### `GET /{toolId}`

Get one native tool definition (schema + cache metadata).

### `POST /{toolId}/execute`

Execute a native Java tool in JVM runtime.

Body:

```json
{
  "agentId": "main-agent",
  "teamId": "ops-team",
  "collaborationSessionId": "7ad8c0bd-7166-418e-bf4b-8fb4f37f5fef",
  "goalId": "7f20a93d-f9e0-48e0-a4e9-6e224f13065a",
  "input": {
    "manifest": {
      "id": "my-plugin",
      "name": "My Plugin",
      "type": "SKILL",
      "version": "1.0.0",
      "author": "dev"
    }
  }
}
```

Current built-ins:

- `tool_registry_inspect`
- `plugin_contract_validate`

## Notes

- Health endpoints are designed for load balancers, orchestrators, and monitoring systems.
- Detailed resource endpoints (`/api/agents`, `/api/tasks`, `/api/providers`, etc.) are documented in dedicated pages.
