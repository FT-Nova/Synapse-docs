# Release Process

This page describes how SYNAPSE backend and documentation releases are validated and published.

## Versioning Model

- Backend (`Synapse`): `vX.Y.Z` and `vX.Y.Z-dev` pre-release tags
- Docs (`synapse-docs`): independent versioning and release cadence
- Security fixes are shipped as explicit hotfix releases

## Backend Release Flow

1. Implement milestone scope.
2. Push changes.
3. Verify GitHub Actions status.
4. If checks fail, hotfix immediately and push again.
5. Create tag and publish release notes.

## Documentation Release Flow

1. Update docs in `synapse-docs`.
2. Push and verify:
   - Documentation CI
   - Deploy Documentation
3. Fix all build and link issues.
4. Tag/publish docs release for milestone completion.

## Observability Release Checklist (v2.2.0+)

- [ ] Monitoring docs include metrics, tracing, probes, and dashboards
- [ ] API docs include health/readiness/liveness endpoints
- [ ] Configuration docs include observability env toggles
- [ ] Operations runbook is present and linked
- [ ] Docs CI and deployment are green

## Rollback Guidance

If regressions are introduced:

1. Revert the failing change set.
2. Re-run CI to validate baseline.
3. Publish a hotfix release with root-cause notes.
